## What is missing

1. A local model server. On this host only a CPU server is realistic: **Ollama** (native Windows install,
   or the `ollama/ollama` Docker image, which needs no host install).
2. Model weights. The runbook names `qwen3:32b` (~20 GB at Q4). It fits in 32 GB RAM but on a 4-core laptop
   CPU it answers at roughly 1–2 tokens/s, which makes a full §62 run take hours and hit the 120–180 s profile
   timeouts. **`qwen3:8b`** (~5 GB) is the closest practical model; `qwen3:4b` is the fallback.
3. A local copy of the air-gapped models file that maps the allowlisted id onto the served name, because
   `config/models.airgapped.yaml` maps `qwen/qwen3-32b` to `qwen3-32b` (the vLLM name).

## Commands the owner would run

Option A, native Ollama (needs the installer; one-time):

```powershell
winget install Ollama.Ollama
ollama pull qwen3:8b
```

Option B, Ollama in Docker (no host install; does not touch the compose stack):

```bash
docker run -d --name airgap-ollama -p 127.0.0.1:11434:11434 -v airgap-ollama:/root/.ollama ollama/ollama
docker exec airgap-ollama ollama pull qwen3:8b
```

Then a local config copy (not committed), e.g. `config/models.airgapped.local.yaml`:

```yaml

    kind: chat
    type: openai_compatible
    egress: internal
    base_url: http://127.0.0.1:11434/v1
    base_url_env: ANALYSTOS_LOCAL_LLM_URL

```

(`ollama create qwen3-8b-8k -f Modelfile`) and map to that name instead, so the declared `context_window`
matches what the server holds.
